# 本実装で対応する予定の型

ベータ版では、ここに挙げる型に対応しない。本実装で、型システムに入れる予定である。

ベータ版の目的は、10進型と金額型のルールを検証することである（README の「ステータス」）。ここに挙げる型は、その範囲を超えるので、本実装に回す。この文書には、何を入れるかと、なぜ入れるかだけを書く。細かい設計は、本実装の開発で決める。

型システムの拡張を一通り調べたうえで、COBOL の代替に効くものとして、次の3つを選んだ。

| 型 | 縛るもの | 先行例 | Zustral での狙い |
|---|---|---|---|
| 篩型（refinement types） | 値 | Liquid Haskell、F* | PIC 句の桁数や、値の範囲を型で表す |
| 単位（units of measure） | 値 | F# | 通貨の取り違えを型エラーにする |
| 情報フロー型（information flow types） | 値の流れる先 | Jif | 個人情報が外へ漏れることを型で防ぐ |

## 1. 篩型

述語の付いた型である。たとえば `{x: Int | 0 <= x < 100}` は、0 以上 100 未満の整数だけを値に持つ。述語が成り立つことは、SMT ソルバでコンパイル時に検証する。

**狙い。** COBOL の PIC 句が表す桁数や、業務で決まっている値の範囲を、そのまま型に書けるようにする。金額は 0 以上、利率は 0 以上 1 以下、といった制約を、プログラマの注意ではなく型で守る。

**ベータ版との関係。** `Decimal[P, S]` は、精度とスケールという桁数の制約を、すでに型に持っている（`docs/decimal.md` の1節）。篩型は、これを値の範囲や、ほかの述語へ広げる。

**本実装で決めること。**

- 述語に書けるものの範囲。たとえば、線形の算術と比較に限るか。
- コンパイル時に証明できないときの扱い。暗黙の実行時検査は入れない（コンセプトの3「明示的であること」）。検査を入れるなら、コードに書かせる。

## 2. 単位

数値に単位を付ける型である。円とドル、メートルと秒のように、単位の違う値を足すと型エラーになる。

**狙い。** 通貨の取り違えを、型エラーにする。

**ベータ版との関係。** ベータ版の金額型は、通貨が違う金額どうしの足し算を型エラーにする（README の「本実装へ切り替える条件」、issue #21）。本実装では、これを通貨に限らない単位の仕組みに広げる。

**本実装で決めること。**

- 単位どうしの掛け算と割り算（たとえば「円／日」）を許すか。
- 金額型の規則（金額×金額は禁止、金額×利率は明示的な丸めで金額に戻す）を、単位の規則としてどう書くか。

## 3. 情報フロー型

値に機密の度合いを表すラベルを付け、機密の値が公開の側へ流れないこと（非干渉性）を型で保証する。

**狙い。** 個人情報を扱うバッチで、氏名や口座番号がログや外部のファイルへ漏れることを、型で防ぐ。

**ベータ版との関係。** Austral から受け継いだケイパビリティは、どの資源にアクセスできるかを縛る。情報フロー型は、どのデータがどこへ流れるかを縛る。両者は補い合う。入出力の先にラベルを付ける必要があるので、I/O ライブラリの設計（本実装で行う）と合わせて決める。

**本実装で決めること。**

- ラベルの種類。たとえば「公開」と「個人情報」の2つから始めるか。
- 機密を外す操作（declassification）。必ずコードに明示して書かせる。
