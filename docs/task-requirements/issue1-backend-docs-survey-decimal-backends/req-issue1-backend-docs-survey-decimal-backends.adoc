== 背景と目的

Zustral（Austral のフォーク）に10進数（Decimal）を持ち込む言語仕様を固める途中にある。
Decimal が乗れる実行時表現の候補が、実際のところ何がどう違うのかが分かっていない。
この違いが、下流のチケットの判断を縛る。

* 0004「スケールは型に入るか、値に入るか」（0001 と 0003 にブロックされる）
* 0005「Decimal は線形リソースか、値型か」（0001 にブロックされる）
* 0008「桁あふれを例外なしでどう扱うか」（0004 と 0005 の後に続く）

チケット番号 000N は issue #N に対応する。

目的:: 0004・0005・0008 を詰める人が、3系統の候補の違いを、このマシンで再実行できる証拠か一次資料に裏付けられた事実として読めるようになること。

利用者は2種類いる。

レポートの読者:: 下流チケットで壁打ちする人。事実と根拠を読み、選定の材料にする。
プローブの再実行者:: レポートの主張を疑う人。1つのコマンドでプローブを再実行し、出力とレポートを照らし合わせる。

== 対象範囲と対象外

=== 対象

3系統（issue が「最低でも」と挙げたもの）:

* mpdecimal（Python の `decimal` が使っている任意精度10進ライブラリ）
* IEEE 754-2008 decimal128（GCC の `_Decimal128` / libdfp / Intel DFP ライブラリ）
* 自前の固定小数点（`__int128` にスケールを添える）

5観点（issue の「知りたいこと」）:

. 確保と解放のモデル
. 精度と桁数の上限、丸めモードの品揃え
. C ABI からの呼び出しやすさ
. 依存とライセンス、ビルドの重さ、プラットフォーム移植性
. 演算結果の決定性

成果物:

* 調査レポート（日本語の文書）
* レポートの事実を裏付けるプローブと、それを1コマンドで再実行する手段
* issue #1 の解消と、地図 issue #9 への記録

=== 対象外

* バックエンドの選定そのもの。0004・0005・0008 の仕事である。
* コンパイラ（`lib/`）と stdlib（`standard/`）への decimal 実装。
* issue #2〜#8 の編集。
* リポジトリ内の `docs/wayfinder/` の変更。トラッカーは GitHub Issues に移っており、`docs/wayfinder/` の扱いは別の PR が受け持つ。

== 要件

レポートの置き場所、プローブの言語とファイル構成、記録した出力の置き場所、決定性を確かめる演算と入力の選び方、Zustral の FFI プローブの組み立て方は設計で決める。
既定の置き場所の候補は `docs/research/decimal-backend-survey/` である。

=== プローブの再実行

REQ-005:: プローブは、再実行者が1つのコマンドで全部を再実行できなければならない。
レポートは、そのコマンドと、再実行に必要な前提（nix、C コンパイラなど）を示さなければならない。
プローブ出力を根拠にする主張は、どのプローブの出力に基づくかを特定できなければならない。

REQ-006:: When 再実行したプローブの出力が、記録した出力と一致しないとき、再実行コマンドは一致しなかったプローブを表示し、失敗の終了状態で終わらなければならない。
If プローブの依存（ライブラリやコンパイラ）をこのマシンで取得できないなら、then 再実行コマンドはそのプローブを未実行として理由とともに表示し、成功の件数に含めてはならない。
未実行だけでは失敗の終了状態にしない。取得できない依存が恒常的にあっても、記録との食い違いを終了状態で検出できるようにするためである。
レポートは、未実行になったプローブに依存する主張を「出典のみ・未実測」として扱わなければならない。

[source,gherkin]
----
@REQ-006
Scenario: 記録と食い違う出力は失敗として見える
  Given あるプローブの出力が、記録した出力と異なる
  When 再実行者が再実行コマンドを実行する
  Then 一致しなかったプローブの名前が表示される
  And コマンドは失敗の終了状態で終わる

@REQ-006
Scenario: 依存を取得できないプローブは未実行として表示される
  Given あるプローブが依存するライブラリを、このマシンで取得できない
  When 再実行者が再実行コマンドを実行する
  Then そのプローブは未実行として、取得できなかった理由とともに表示される
  And そのプローブは成功の件数に含まれない
  And ほかのプローブがすべて記録と一致すれば、コマンドは成功の終了状態で終わる
----

=== C ABI と Zustral からの呼び出し

REQ-007:: レポートは、各系統の10進値を Zustral の `Foreign_Import` で扱えるかを示さなければならない。
示す内容は、値のまま渡せるか、ポインタ越しなら渡せるか、C の薄い包み（シム）が要るか、である。
Zustral 側の制約（FFI が受け付ける型）は、コンパイラのソースを根拠に示さなければならない。
+
Where Zustral コンパイラをこのマシンでビルドできる場合、レポートは、各系統を `Foreign_Import` で呼ぶ Zustral プログラムを実行した結果を根拠にしなければならない。
If コンパイラのビルドが失敗する、または設計で決めた手間の上限を超えるなら、then レポートはその理由を記録し、C だけのプローブとコンパイラのソースの引用を根拠にしなければならない。

[source,gherkin]
----
@REQ-007
Scenario: コンパイラをビルドできれば Zustral プログラムで確かめる
  Given Zustral コンパイラをこのマシンでビルドできる
  When 再実行者が再実行コマンドを実行する
  Then 各系統を Foreign_Import で呼ぶ Zustral プログラムの出力が表示される

@REQ-007
Scenario: コンパイラをビルドできなければ理由を残して C だけで確かめる
  Given Zustral コンパイラのビルドがこのマシンで現実的でない
  When 読者がレポートの C ABI の節を読む
  Then ビルドできなかった理由が書かれている
  And 根拠は C だけのプローブとコンパイラのソースの引用である
----

== 前提と制約

判断に効いた事実だけを置く。ほかの調査結果は事前調査レポートを参照する。

* Zustral の FFI は128ビット整数を持たない。整数の幅は 8/16/32/64/ByteSize/Index だけである（`lib/Type.ml:22-29`）。
* Zustral の FFI はレコードの値渡し、`Unit` の戻り値、参照を受け付けない（`lib/CodeGen.ml:554-591`）。
* コンパイラの CLI には、追加の C ファイルやリンクするライブラリを渡すフラグがない。外部ライブラリとのリンクは `--target-type=c` の出力を自分で C コンパイラに渡す（`lib/CliParser.ml:55`、`lib/Util.ml:202-203`）。
* `Foreign_Import` の既存例が `examples/ffi/FFI.aum:1-14` にある。
* このマシンの gcc 13.3.0 は `__DECIMAL_BID_FORMAT__=1`、`__DEC128_MANT_DIG__=34`、`__SIZEOF_INT128__=16` を定義する（`echo | gcc -dM -E -` の出力）。
* clang は PATH にない。nixpkgs（rev `674a2028661e`）から clang 21.1.8 を取れる。
* nixpkgs には mpdecimal 4.0.1（BSD-2-Clause）がある。libdfp、Intel DFP、decNumber の名前のパッケージは見つからなかった。
* wayfinder のトラッカーは GitHub Issues である。地図 issue #9 の「トラッカーの約束（GitHub Issues）」では、確保は issue へのアサインで行い、解消は解消コメントの投稿、issue のクローズ、地図の「ここまでの決定」への1行で行う。issue #1 は seiei-sogen にアサイン済みで、確保は済んでいる。

== 正常系、境界条件、失敗時の結果

正常系:: 再実行コマンドが全プローブを実行し、出力がレポートの記録と一致して、成功の終了状態で終わる。
境界条件:: 依存を取得できないプローブ（REQ-006）、clang でコンパイルできない系統（REQ-008）、コンパイラをビルドできない場合（REQ-007）。どれも未実行や理由として見え、成功に数えない。
失敗時の結果:: 出力が記録と食い違えば、再実行コマンドがそのプローブを名指しして失敗する（REQ-006）。

== 未確定事項

どれも、結果ごとの扱いを REQ-006・REQ-007・REQ-008 が決めているため、このまま設計と実装に進める。

. Zustral コンパイラが、このマシンの nix dev shell で現実的な時間にビルドできるか。確認方法: `flake.nix` の dev shell で `make` を実行する。結果は REQ-007 の分岐を決める。
. mpdecimal のヘッダと、Zustral が生成する `au_*` 型の `extern` 宣言を同じ翻訳単位に置いたときに型が衝突するか。確認方法: 小さな Zustral プログラムを `--target-type=c` で出し、mpdecimal とリンクする。結果は FFI プローブの組み立て方を決める。
. libdfp と Intel DFP を、このマシンでソースからビルドできるか。確認方法: 各プロジェクトの公式リポジトリのビルド手順を試す。できなければその主張は出典のみになる。
. nixpkgs の clang 21.1.8 が、このマシンで `_Decimal128` をコンパイルできるか。確認方法: `nix shell nixpkgs#clang` で小さなプログラムをコンパイルする。できなければ REQ-008 の clang 比較は未実行になる。

== 判断から学べること

実装前の判断として記す。効果は実証していない。

. 調査と選定を分けたチケットでは、調査レポートに推奨を書かない。
** 兆候: research チケットの後ろに、それにブロックされる grilling チケットが並んでいる。
** 使える条件: 下流に選定を担う場が別にあるとき。
** 使わないほうがよい条件: 調査と決定が同じ人・同じ場で完結し、推奨がないと次に進めないとき。
** 関連: REQ-009、採用した意思決定の表。
** 検索語: wayfinder research ticket、separation of fact-finding and decision。
. 観測できる主張と出典だけの主張を、文の単位で分ける。
** 兆候: 「プラットフォームをまたいで同じ答えになるか」のように、手元で確かめられない性質を問われている。
** 使える条件: 読者が主張を再実行で確かめる手段を持つとき。
** 使わないほうがよい条件: すべての主張が出典に基づく文献調査で、再実行する対象がないとき。
** 関連: REQ-003、REQ-004、REQ-006。
** 検索語: reproducible research、evidence labeling。
. C ライブラリの呼びやすさは、ライブラリ側より先に言語の FFI の型対応表で決まることがある。
** 兆候: 比べたい値型が128ビットや構造体の値で、言語の FFI がその幅や値渡しを持たない。
** 使える条件: C バックエンドや FFI を持つ言語から C ライブラリを評価するとき。
** 使わないほうがよい条件: 言語の FFI が対象の型を直接表せるとき。
** 関連: REQ-007、`lib/CodeGen.ml:554-591`、`lib/Type.ml:22-29`。
** 検索語: FFI type mapping、C ABI 128-bit by value、shim function。
