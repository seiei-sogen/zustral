超やさしい解説: 10進バックエンド調査の実装計画（issue #1）

ひとことで言うと

「お金の計算に使う10進数の部品」の候補を3つ並べて、違いを証拠つきで書いたレポートを作る計画です。証拠は、誰でもコマンド1回でやり直せる小さなプログラムの出力です。

どれを使うかは、この計画では決めません。決めるのは後のチケット（0004・0005・0008）です。

1. 何を比べるの？

10進数を計算機で扱う方法の候補は3つです。

候補たとえると
mpdecimalいくらでも桁を増やせる電卓。ただし使うたびにメモリを借りて、返す必要がある。Python の decimal の中身。
decimal128（GCC の _Decimal128、libdfp、Intel DFP）34桁までの決まった大きさ（16バイト）の電卓。国際規格（IEEE 754-2008）どおりに動く。同じ規格の実装が3つある。
__int128 固定小数点とても大きな整数に「小数点は右から18桁目」と決めて使う自作の電卓。丸め方は自分で書く。

見る点は5つです。メモリの借り方と返し方、桁数と丸め方、Zustral から呼べるか、入手しやすさとライセンス、何度やっても同じ答えか。

2. 証拠はどうやって作るの？

候補ごとに小さな C のプログラム（プローブ＝「探り針」）を書き、計算結果を key=value の行で出させます。その出力を expected/ に記録しておきます。

再実行の係が run.sh です。プローブを作り直して2回動かし、記録と同じかを比べます。結果は3種類だけです。

なぜ「未実行」を失敗にしないの？ clang は _Decimal128 を扱えないので、その組み合わせはいつも動かせません。これを失敗にすると、いつも失敗になって本当の食い違いが見えなくなります。だから「未実行」は理由つきで見せるだけにし、成功にも数えません。

なぜ「ビルド失敗」は不一致なの？ 部品はそろったのに作れないのは、プローブが壊れているからです。「未実行」に混ぜると、壊れたものが成功に見えてしまいます。

照合も記録の作り直しも、コマンド1つです。

docs/research/decimal-backend-survey/run.sh          # 照合する
docs/research/decimal-backend-survey/run.sh --record # 記録を作り直す

このマシンでの結果は 一致 18 / 不一致 0 / 未実行 4 です。未実行の4つは、clang で _Decimal128 を使う組み合わせです。

3. 作る順番（タスク）

タスクやること（やさしく）
T1run.sh と一番かんたんな候補（__int128）を作り、「一致・不一致・未実行」が正しく出るところまで通す。
T2GCC の _Decimal128 のプローブ。clang では作れないので「未実行」と理由が出ることも確かめる。
T3mpdecimal のプローブ。メモリを何回借りるかも数える。
T4libdfp と Intel DFP をソースから組み立ててプローブを動かす。ネットワークを止めると「未実行」になることも確かめる。
T5Zustral のプログラムから Foreign_Import で各候補を呼ぶ。Zustral には128ビットの型がないので、16バイトの箱へのポインタで渡す。
T6日本語のレポート README.md を書く。事実の文には必ず証拠（プローブの行か、資料の URL と版）を付ける。
T71回の実行で全部が通り、作業ツリーが汚れないことを確かめる。
T8commit の後に、きれいな作業ツリーでもう一度実行する。通ったら issue #1 に答えを書いて閉じ、地図 issue #9 に1行足す。

4. 正しさはどう確かめるの？

専用のテスト道具は足しません。わざと壊して、run.sh の表示が変わるかを見ます。終わったら必ず元に戻します。

壊し方見えるはずのもの
記録の1行を書き換える（改ざん）その候補が「不一致」になり、差分が出て、失敗で終わる。
ダウンロードを止める（curl 遮断）libdfp と Intel DFP が「未実行」になり、理由が出る。失敗にはならない。
コンパイラのビルド時間の上限を 0.01 秒にするZustral のプローブが「未実行」になる。
2回の実行で出力が変わるようにして --record する「不一致」になり、両方の出力が出る。記録は書き換わらない。

もう1つ大事なことがあります。--record は「今の出力」をそのまま正解として保存します。プローブが間違っていても正解になってしまうので、記録を作る前に、算数や規格から分かる値（たとえば 1/3 は3が34個）と手で照らしました。

5. やらないこと

  • どの候補を使うかを決めること（0004・0005・0008 の仕事）。
  • コンパイラ（lib/）や標準ライブラリ（standard/）に10進数を実装すること。
  • 速さを測ること、別の種類のマシンで測ること。
