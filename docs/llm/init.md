Austral Programming Language

https://github.com/austral/austral

あるじゃん。

これをZustralという名前でフォークして、セルフホスティングを目指す。

そして、用途はCOBOLの代替になる金融とかの10進法計算に特化するってのはどうよ？

着眼点は良いです。Australの思想（暗黙の変換なし、例外なし、演算子の優先順位すらなし、Ada風のトラップ演算）は、実は「驚きゼロ」を求める金融バッチの文化とかなり相性がいい。COBOLの後継を名乗る言語はいくつもありましたが、線形型を持ち込んだものはない。ここで面白いのは、**複式簿記そのものが線形型と同型**な点です。仕訳（debit/credit）を線形リソースにすれば「一度だけ消費される＝二重計上も計上漏れも型エラー」になる。これはZustralの独自のセールスポイントになり得ます。

10進特化の設計論点としては：

- **型レベルの精度とスケール**。COBOLの `PIC 9(7)V99` はスケールが型に入っている。`Decimal[7,2]` のような値パラメータ付き型が要る。Australのジェネリクスは型パラメータのみなので、ここが最初の言語拡張になる
- **丸めの明示化**。`round_half_even` / `truncate` を別の演算にする。暗黙変換禁止のAustral哲学と完全に整合する。COBOLバグの大半はここに棲んでいる
- 実装はまず C バックエンド経由で mpdecimal か IEEE 754-2008 decimal128 にリンクすれば動く

正直に言うと、順序は「decimal → セルフホスティング」が現実的です。セルフホスティングにはまず文字列・マップ・ファイルIOの揃ったstdlibが要り、現状のAustral stdlibは最小限。しかも分割コンパイル未対応なので、コンパイラ規模のコードを書く前にそこも直すことになる。逆に言えば、decimal拡張だけならOCamlの既存コンパイラに型と組み込み演算を足すだけで動くものが作れるので、Zennの連載ネタとしても一本目がすぐ出せます。縁起言語のRust経験がそのまま活きる規模感ですね。
