= 引き継ぎメモ

== 30秒で分かる要約

* Zustral（Austral というプログラミング言語のフォーク）に10進数計算を入れる構想を、計画用スキル wayfinder で整理した。
* 成果物は「地図」1件と「決定チケット」8件。すべて新規ファイルとして `docs/wayfinder/` に置いた。
* チケットは8件とも未着手。1件も解消していない。
* 調査チケット3件をサブエージェント（自動で調べ物をする別プロセス）に投げたが、ユーザーが途中で停止した。調査結果は残っていない。
* コードは1行も変更していない。作成したファイルはすべて Git 未追跡でコミットもしていない。

== 依頼されたこと

ユーザーは `/wayfinder` というスキルを、`docs/llm/init.md` を引数にして実行した。

`init.md` に書かれていた構想は次のとおり。

* Austral（線形型を持つ新しい言語）を Zustral という名前でフォークする。
* セルフホスティング（Zustral 自身で Zustral コンパイラを書くこと）を目指す。
* 用途は COBOL の代替。金融向けの10進数計算に特化させる。

wayfinder は「計画する、作らない」スキルである。

* 作るものを実行単位に分割するのではない。
* 「解消すると決定が1つ確定する問い」をチケットにして、地図の上に並べる。
* 実装は地図の外に置く。

== 決まったこと

ユーザーが選択した決定は2つある。どちらも会話の中で明示的に選ばれた。

=== 決定1: 目的地は「Zustral の Decimal 言語機能の設計仕様」

* 提示した3案のうち、A案が選ばれた。
* A案は、decimal の言語仕様を実装に着手できる粒度まで固めることを目的地とする。実装そのものは含まない。
* 選んだ理由は2つある。
** `init.md` 自身が「decimal → セルフホスティング」の順序を現実的だと述べている。
** decimal の型設計が、stdlib の形も C バックエンドの選択も簿記ライブラリの可否も決めてしまう。

=== 決定2: 仕様の範囲は「型と算術の意味論 + 実行時表現とバックエンド」

* 提示した3案 (a)(b)(c) のうち、(b) が選ばれた。
* (a) は型と算術の意味論だけ。(b) はそれに実行時表現とバックエンドの選択を加える。(c) はさらに stdlib の API まで含める。
* (b) を選んだ理由は、実行時表現が型の形を縛るからである。
** Austral には GC（ガベージコレクション、不要になったメモリを自動回収する仕組み）がなく、線形型がある。
** 任意精度の10進ライブラリを使うとヒープ確保が必要になり、Decimal 値そのものが線形リソースになる。
** 固定幅の表現なら、既存の `Float64` と同じ非線形の値型でいられる。
* (c) に当たる Money 型や複式簿記の線形リソースは、スコープ外に置いた。decimal の土台が固まってから別の地図として引き直す前提である。

== 終わったこと

=== イシュートラッカーの選定

* wayfinder は本来、地図とチケットをリポジトリのイシュートラッカーに置く。
* このフォークは GitHub の Issues が無効になっている（`gh repo view` で `hasIssuesEnabled: false` を確認）。
* トラッカーも呼び出し側から渡されなかった。
* そのため、スキルの既定である local-markdown 方式を採り、Markdown ファイルとして `docs/wayfinder/` に置いた。
* ファイル上での約束事（確保、解消、ブロック関係、フロンティアの探し方）は `docs/wayfinder/map.md` の「トラッカーの約束」節に書いてある。

=== 地図の作成

`docs/wayfinder/map.md` を作った。内容は目的地、メモ、ここまでの決定（空）、未特定、スコープ外。

スコープ外に置いたものは次の4つ。

* セルフホスティング。stdlib と分割コンパイルが前提になるため、目的地の遥か先にある。
* 複式簿記の線形リソースと Money 型。
* 分割コンパイル、パッケージマネージャ、ビルドシステム。
* Zenn 連載などのコンテンツ化。

未特定（まだチケットにできない霧）に置いたものは次の5つ。

* リテラルと型の境界。`1.23` をどう decimal として型付けするか。
* 比較と typeclass。`Equality` と `Order` のインスタンスをどう与えるか。
* 文字列化とパース。COBOL の編集項目（`PIC ZZZ,ZZ9.99`）相当をどこに置くか。
* 設計を裏取りするプロトタイプの範囲。
* 検証の置き場。既存の `test-programs/` で10進の意味論をどう golden test にするか。

=== チケット8件の作成

フロンティア（今すぐ着手できるチケット）は3件ある。いずれも調査型で、他のチケットにブロックされていない。

* 10進バックエンドの実像を掴む（`0001-decimal-backend-survey.md`）。mpdecimal、IEEE 754-2008 decimal128、自前の固定小数点について、確保モデル、精度、丸めモード、C からの呼びやすさ、依存とライセンス、プラットフォーム間の決定性を調べる。
* Austral の型パラメータ機構に値パラメータを足す道筋を掴む（`0002-value-parameter-generics.md`）。`Decimal[7, 2]` のように型が数値を取れるようにした場合、コンパイラのどこに変更が波及するかを調べる。値に持たせる代替案の costs も併せて調べる。
* COBOL の10進意味論のうち何を継ぐか、材料を揃える（`0003-cobol-decimal-semantics.md`）。`PIC` 句、`COMPUTE` の中間結果精度、`ROUNDED`、`ON SIZE ERROR`、`GIVING` の暗黙切り捨てを調べる。

ブロックされているチケットは5件ある。括弧内は待っている相手。

* スケールは型に入るか、値に入るか（`0004`）。待ち: `0001` と `0003`。この地図の要であり、下流の全部を決める。
* Decimal は線形リソースか、値型か（`0005`）。待ち: `0001`。
* 除算のスケールを誰が決めるか（`0006`）。待ち: `0004`。
* 丸めをどう明示するか（`0007`）。待ち: `0006`。
* 桁あふれを例外なしでどう扱うか（`0008`）。待ち: `0004` と `0005`。

== 確認結果

=== コマンドで確かめた事実

チケットの前提として、リポジトリを調べて次を確認した。いずれも推測ではない。

* このリポジトリは Austral の素のフォークである。`README.md` の見出しはまだ `# Austral` のままである。
* コンパイラは OCaml で書かれており、`lib/` 配下に約100ファイルある。
* stdlib は `standard/src/` に9モジュールのみ（String、Buffer、Box、StringBuilder、Order、Equality、Bounded、Tuples ほか）。マップもファイル IO もない。
* 分割コンパイルは未対応。`README.md` の207行目に明記がある。`ROADMAP.md` にも「複雑な取り組みになる」と書かれている。
* Austral のジェネリクスは型パラメータのみを取る。値パラメータの仕組みはない。
* GitHub の Issues がこのフォークでは無効である。

== 注意点

=== wayfinder のルール

* 1セッションで2件以上のチケットを解消してはいけない。調査型のチケットだけが例外である。
* 作業を始める前に、チケットを確保する。local-markdown 方式では front matter の `assignee` を埋めることが確保にあたる。未クローズかつ `assignee` 空のチケットは未確保とみなす。
* チケットを解消したら、本文末尾に `## 解消` 節として答えを書き、`status: closed` にし、地図の「ここまでの決定」へ1行追記する。
* 答えによってチケットが目的地の先にあると分かった場合は、解消せずクローズしてスコープ外の節に1行残す。

=== この環境固有の事情

* wayfinder が前提にしている `research` スキルと `prototype` スキルは、この環境にインストールされていない。
* `grilling` スキルも存在しないため、`grilling-jp` で代用した。`domain-modeling` は存在する。
* wayfinder は調査結果を使い捨ての `research/<名前>` ブランチに置けと指示している。しかし local-markdown 方式ではチケット自体が作業ブランチ上にあり、別ブランチに分けるとチケットと答えが離れてしまう。そのため `docs/wayfinder/research/` に置く方針にした。この方針はまだ実行していない。
* サブエージェントを使う場合は、チケット本文を指示書として渡す形になる。前回はこの形で起動した。
