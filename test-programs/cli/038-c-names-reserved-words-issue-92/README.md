Pins which names get the reserved-word escape (`au_ckw_`) in the generated C (issue #92). Every name in `forms.zum` starts with a C reserved word, and some of them are one. This runner only sees that the compiler succeeds; the generated C is compared by `tools/refactoring/equivalence.py`. The target is C because there is no C function `format` to link.

- A name the user wrote in Zustral gets the escape when it is a C reserved word, and only then. That is a variable, a parameter, a loop variable, a record slot, a union case, a constant, and a parameter in the `extern` declaration of a foreign function: `au_ckw_double`, `struct {} au_ckw_default;`, `extern au_int32_t format(au_nat8_t* au_ckw_const);`. A name that only starts with a reserved word is written as it is: `structure`, `forms____integer`.
- The name in `External_Name` reaches C as written, where it is declared and where it is called: `extern au_int32_t fork(au_int32_t intArg);`, then `fork(intArg)`. The wrapper of an exported function is `double_it`. The compiler accepts only an `External_Name` that is a C identifier and not a C reserved word, so the name needs no escape.
