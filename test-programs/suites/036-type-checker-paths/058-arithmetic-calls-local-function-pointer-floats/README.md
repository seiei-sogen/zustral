Pins the same for float literals: both operands arrive under a cast to Float64, and are accepted for Float32 parameters. The function is never called, because the generated C calls the Float32 function through a pointer to a function of Float64 parameters (lib/TypeCheckExpr.ml, augment_arithmetic; lib/TypeMatch.ml, match_type_with_value). Nothing in this directory states the expected C; the equivalence check (tools/refactoring/equivalence.py) compares the generated C with that of the base compiler.
