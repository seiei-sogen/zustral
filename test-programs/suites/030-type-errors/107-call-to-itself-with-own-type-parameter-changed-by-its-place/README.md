Test that, when a generic function calls itself with a value of its own type parameter `T`, the place of the call cannot make that `T` another type. No parameter of `wrap` mentions its `T`, so the place of the call gives the call its `T`, here `Int32`. The `T` of the argument `first` is the caller's, and stays `T`: the call `wrap(first, false)` is a `Two[Int32, T]`, not a `Two[Int32, Int32]`. Before, the two were one type variable and the place bound both: the call was accepted, and the C compiler rejected the program (`incompatible types when assigning`). This is the form that the last review of issue #151 left open (issue #156).
